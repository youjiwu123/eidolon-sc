# 群聊：多个人一个对话，谁该接话由模型判断，她们之间也能聊几句

Status: draft

术语以 `GLOSSARY.md` 为准。本设计不改动单聊的任何行为。

## Problem Statement

- **只能一对一。** `conversations` 的 `character_id` 写死一个角色，254 个对话全是单聊；想同时和两三个人说话，只能开两个窗口来回切。
- **角色之间没有同台。** 剧情库里 6,876 集有 2,230 集是多角色同台，但对话里永远只有一个人；她和别的偶像怎么相处，只能靠剧情检索间接体现。
- **没有「在场」的概念。** 提示词里只有「你和制作人」，没有「还有谁在」，所以她既不会提到别人，也不会让别人插话。

## Solution

**群聊是一个新东西，不改单聊。** 新表、新接口、新回合，单聊的代码路径一行不动。

- 用户建群、拉人（2–4 人），群里只做文字，没有语音、没有照片、没有礼物、没有搭话、没有电话。
- **谁接话由模型判断**：每次用户发言后，让判断模型看一遍「在场有谁 + 最近几句」，挑出该接话的 1–2 人，并给出顺序。挑不出来就都不回（用沉默表示她们在听）。
- **她们之间能聊，但有上限**：一轮里最多再让另一个角色接一次别人的话（`max_exchanges`，默认 1），之后必须等用户说话，避免自说自话停不下来。
- **好感度不动**：群聊里不判定、不改变任何人的好感度，也不触发冷却、厌倦和劝退。想看好感变化，回单聊。

## User Stories

1. 作为用户，我想把真乃、羽那、ルカ 拉进一个群，一起聊演出的事，而不必开三个窗口。
2. 作为用户，我希望她们各自用自己的口吻说话，而不是三个人说得一模一样。
3. 作为用户，我希望我说的话由最该回应的人接，而不是每次都三个人一起回。
4. 作为用户，我希望她们能互相接话（羽那说完，ルカ 可以插一句），但不要两个人自顾自聊个没完。
5. 作为用户，我希望看到每条消息是谁说的，头像和名字要清楚。
6. 作为用户，我希望群聊里说的话不会被算进好感度，避免我随便开玩笑掉好感。

## 数据

```sql
-- 群聊本体。单聊仍是 conversations，两者不混。
group_conversations(id, user_id, created_at, title, participants JSON)  -- participants: ["mano","hina","luca"]

-- 群里的消息。speaker_id 是角色的 character_id；用户发言时它是 NULL，role='user'。
group_messages(id, group_id, role, speaker_id, segments JSON, created_at)
```

`segments` 与单聊同构（`[{"ja": ..., "zh": ...}]`），复用现有的解析器和前端段落渲染。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/groups` | 建群，body `{character_ids: [...]}`，返回 `{id}` |
| `GET` | `/api/groups` | 我建的群及最后一条消息 |
| `GET` | `/api/groups/{id}/messages` | 群消息 |
| `POST` | `/api/groups/{id}/turns` | 我发言，SSE 流出她们的回话（每条带 `speaker_id`） |
| `DELETE` | `/api/groups/{id}` | 解散 |

## 回合怎么做

1. 存下用户这条消息。
2. **选人**：调判断模型，输入「在场角色 + 各自一句话人设 + 最近 6 条消息 + 用户这句」，输出 `{"speakers": ["luca", "mano"]}`（0–2 人，有序）。判断失败就退化成「上一条说话者之外的第一人」。
3. **依次生成**：对每个 `speaker`，用她的完整提示词（人设 + 世界 + 档位人设 + 群聊规则 + 群历史）生成回复，存成一条 `group_messages`。
4. **互相接话**：第一轮结束后，若 `max_exchanges` 还有余量且上一条不是她说的，再选一个「想接话」的角色生成一条；否则结束。

群聊规则的要点（新增提示词块）：

- 在场有谁、你和她们各自怎么称呼对方（取人设卡里的「对他人的称呼」）。
- 只写你自己的台词和动作，**不要替别人说话、不要描写别人的台词**。
- 一轮通常一两句；别人说完你可以只回一句反应。
- 不要每句都点别人的名字；不要每次都要总结。

## 前端

- 对话列表里群聊和单聊并列，群聊用叠头像。
- 群聊页头部显示所有参与者；消息气泡旁带头像和名字（用户的不带）。
- 输入框与单聊一致；发送后按 SSE 顺序显示，谁在打字的指示只需显示「有人在说」。
- 群里不显示好感度心形。

## 不做的（本轮）

- 语音（通话、语音消息）
- 照片、礼物、搭话、赞助、电话
- 群聊里的记忆与剧情检索（先用各自人设，检索留到下一轮）
- 群聊改名、拉人/踢人
- 好感度、冷却、厌倦

## 分阶段

1. **后端骨架**：表、建群/列表/消息接口、回合（先固定顺序全回，不做选人），跑通 2 人。
2. **选人**：判断模型挑该接话的人 + 互相接话的 `max_exchanges`。
3. **前端**：群聊列表、群聊页、SSE 渲染。
4. **收敛**：提示词调优、测试、`HANDOFF-NOW.md` 记录。

## 验收

- 建一个 3 人群，发一句「今天演出怎么样？」，能看到 1–2 个人回复，各自是自己的语气。
- 回复里没有「替别人说话」的段落。
- 单聊行为与改动前完全一致（现有测试全绿）。
- 群聊不改动 `affinities` 表。
